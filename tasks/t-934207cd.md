## Description

Readiness: permission + read path + `KanbanService.create` all exist; `scarf.kanban.create` is a clean wire-up. ONE design call first — `KanbanService` has NO generic "move", only status-specific verbs (complete/block/schedule/promote/archive), so `scarf.kanban.move` needs a verb-mapping decision (or a new transition method). Not urgent: this is the natural v2 of the mini-app surface; build it when there's real demand for interactive (not just read-only) mini-apps.

Wire `scarf.kanban.move` / `scarf.kanban.create` from mini-apps behind the existing `kanban:write` permission. The permission already exists but the surfaces are intentionally NOT wired — read-only v1 by design (Phase-1 Decision #4 / the Mini-App Bridge Contract) to keep the trust surface small for untrusted/agent-generated web content. Now that the read path (`scarf.kanban.read` / `query:kanban.tasks`) is proven, add the write surfaces in `ScarfMiniAppBridge` + `KanbanService` (tenant-scoped to the project), keep them in the SENSITIVE set (default-off for `generated:true` apps), add `ScarfMiniAppBridgeTests` coverage, and document them in the `scarf-miniapp-author` skill. The one intentionally-later permission from the Phase-1 plan.
