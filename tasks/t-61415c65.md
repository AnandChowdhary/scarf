## Description

Follow-up to t-72fc3790 (process-cwd fix). Now that iOS cd's into the project so Hermes reads AGENTS.md, the CONTENT iOS writes is deficient.

FACTS (source-verified 2026-06-28):
- iOS `ProjectContextBlock.renderMinimalBlock` (ScarfCore) emits only: project name, dir, dashboard path, slash commands. Its own doc says it "Omits the template-manifest + cron-job sections that the Mac service fills in — ScarfGo v1 doesn't surface those concepts yet."
- Mac `ProjectAgentContextService.renderBlock` emits the FULL block: registered cron jobs (filtered by `[proj:<id>]`/`[tmpl:<id>]` via HermesFileService.loadCronJobs), config field NAMES (manifest schema, secret-safe), template id/version, kanban tenant, uninstall manifest, slash commands, + a static "Scarf platform reference" section (dashboards/cron/skills/kanban/presets/export).
- `applyBlock` replaces the inclusive marker region, so an iOS project-chat start OVERWRITES a richer Mac-written block with the minimal one → cron disappears from the agent's context; the block flip-flops by last-writer. This violates the stated cross-platform byte-identical invariant in ProjectContextBlock.swift:12-15.
- Impact (Alan): for projects whose work IS scheduled jobs (self-learning agents + cron), the iOS agent is blind to them.

DATA ALREADY SHARED (iOS-capable via transport/SFTP): ProjectStore (ScarfCore) facet readers — templateInfo, cronJobIds + loadCronJobs (cronJobsJSON), secretKeys, memoryBlockId. IOSCronViewModel also loads cron. HermesCronJob/CronJobsFile are shared models. Only Mac-only piece: HermesFileService + the renderer itself.

PLAN (Option A — unify, recommended):
1. Move the FULL block renderer into ScarfCore as a pure function `ProjectContextBlock.renderManagedBlock(BlockInput)` (BlockInput = resolved fields: name, path, templateInfo, configFields, cronLines, slashNames, kanbanTenant, lockPresent). Pure → testable, byte-identical both platforms.
2. Shared gatherer (ProjectStore) builds BlockInput from ScarfProject + transport reads (reuse existing facet readers; add a lightweight manifest config-schema projection for the config-fields line so it matches Mac's schema-based output, not just secret keys).
3. Mac `ProjectAgentContextService.renderBlock` delegates to the shared renderer (guarded by existing ProjectAgentContextServiceTests: byte-output, idempotency, secret-safety).
4. iOS: replace renderMinimalBlock at resetAndStartInProject with the shared full renderer; ALSO refresh the block on the RESUME path (currently writes nothing) so dynamic cron is fresh — mirroring Mac's "rewrite on every project-scoped chat start".
5. Tests: shared renderer byte/round-trip/idempotency/secret-safety; iOS gathers cron over SFTP (cron line present). Adversarial audit. Commit (no push).

Blast radius: touches a WORKING Mac feature (renderer refactor) — mitigated by existing Mac tests. Alternative (Option B, iOS-only add-cron) is faster but keeps two divergent renderers (the divergence that caused this) and perpetuates the byte-identical-invariant violation.
