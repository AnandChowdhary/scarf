## Description

Surfaced by the t-69ccb849 fresh-eyes audit (2026-06-28). `ProjectTemplateInstaller.createCronJobs` (scarf/scarf/Core/Services/ProjectTemplateInstaller.swift:237) forwards `--deliver <v>` to `hermes cron create` UNCONDITIONALLY — the identical bug t-69ccb849 fixed for FleetApplyExecutor, on a sibling surface. If a template ships a cron job with `deliver: all` (ProjectTemplateExporter.strip copies deliver verbatim, so a template exported from a v0.14 host carries it) and is installed onto a PRE-v0.14 host, `hermes cron create --deliver all` argparse-fails → `ProjectTemplateError.cronCreateFailed` is THROWN (line ~258) → the WHOLE template install aborts. Arguably MORE severe than the fleet case (which only fails one job).

Fix: gate `--deliver all` on the install-target host's HermesCapabilities.hasCronDeliverAll, like FleetApplyExecutor now does. The installer can't directly reuse FleetApplyPlan.cronCreateArgs (it builds from the template's TemplateCronJobSpec model + does {{PROJECT_DIR}} token substitution, not HermesCronJob + path rewrite), so either (a) probe `context.runHermes(["--version"])` + HermesCapabilities.parse once and drop `--deliver all` when unsupported, or (b) generalize the gating. Single-host install, so the host version is knowable. Pairs with t-69ccb849.

## Artifacts

DONE 2026-06-28. ProjectTemplateInstaller no longer aborts a template install on a pre-v0.14 host carrying a `deliver: all` cron job.

ROOT CAUSE: ProjectTemplateInstaller.createCronJobs:237 forwarded `--deliver` unconditionally; on a pre-v0.14 install host `hermes cron create --deliver all` argparse-fails → ProjectTemplateError.cronCreateFailed THROWS → whole install aborts.

FIX (DRY with t-69ccb849):
- ScarfCore HermesCapabilities: NEW `supportsCronDeliver(_ deliver:) -> Bool` — false only when deliver=="all" && !hasCronDeliverAll; nil/empty + specific/composite platforms always true. The single shared cron-deliver gate.
- Refactored FleetApplyPlan.cronCreateArgs (from t-69ccb849) to use it — behavior-preserving (cronArgs tests still green).
- ProjectTemplateInstaller.createCronJobs: probe the install host once (context.runHermes(["--version"]) → HermesCapabilities.parse; fail→.empty=conservative); forward --deliver only when caps.supportsCronDeliver(deliver), else drop + log warning. Job is created with default delivery instead of aborting the install.

WHY drop-not-throw: matches FleetApplyExecutor philosophy — a degraded-but-created job beats a failed install. Installer has no per-field UI result channel (returns [String] names), so the downgrade is logged (proportionate for a one-shot guided install; templates with deliver=all are rare/first-party).
