## Description

Surfaced by the post-fix fresh-eyes audit (2026-06-28, Finding 4) of b421280. Now that a project chat spawns `hermes acp` with cwd=project, Hermes auto-loads + injects that project's context files (AGENTS.md / CLAUDE.md / .cursorrules — first match) into the agent's system prompt the moment a chat starts. This is inherent to Hermes's context-file model (NOT a Scarf bug), but Scarf's project chats now trigger it: a project obtained from an untrusted source (e.g. a cloned repo carrying a hostile CLAUDE.md/.cursorrules) becomes a prompt-injection vector into the agent with no user opt-in beyond opening a chat. Hermes does security-scan context files for prompt injection before loading (per its tips), which mitigates but doesn't eliminate.

Options: (1) release-note awareness line for v-next ("opening a project chat loads that project's AGENTS.md/CLAUDE.md/.cursorrules"); (2) a future "trust this project's context files?" affordance (first-open prompt, persisted per project id) similar to the mini-app permission gate. Low priority; design-only for now.
