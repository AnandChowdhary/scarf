## Description

Follow-up to t-565f8d45 (which fixed NEW project chats). Pre-existing gap, NOT the original report: when a project chat is RESUMED (ProjectSessionsView → coordinator.selectedSessionId → ChatViewModel.resumeSession → startACPSession(resume:) with projectPath=nil), or auto-reconnected (ChatViewModel.swift:1345 reconnect loop), or typed into a blank chat (autoStartACPAndSend, ChatViewModel.swift:632), the `hermes acp` process AND the ACP session/new both use cwd = home (resolvedUserHome), not the project dir. So a resumed/reconnected project chat loses project context (AGENTS.md) AND tool cwd — same root cause as t-565f8d45 (Hermes reads context files from the process cwd).

Fix: thread the project path through the resume/reconnect/auto-start paths so they also call `ACPClient.forMacApp(projectCwd:)` + pass the project cwd to newSession/loadSession/resumeSession. The project path for a resumed session must be recovered — either pass it through the resume handoff (ProjectSessionsView sets only selectedSessionId today; add a sibling slot like the existing pendingProjectChat), or resolve session→project from SessionAttributionService / the session's stored cwd. Add coverage mirroring the new-chat path.

Infra is already in place (makeProcess(executable:args:cwd:) on Local+SSH transports + ACPClient.forMacApp(projectCwd:)) — this is just threading the project path into the other three ACP-start sites.
